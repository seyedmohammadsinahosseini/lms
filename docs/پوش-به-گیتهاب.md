# پوش کردن پروژه روی گیت‌هاب

## چرا نمی‌توان از داخل workspace پوش کرد؟

پوش کردن نیاز به **احراز هویت** دارد. محیطی که پروژه در آن ساخته و کامیت شد،
هیچ توکن یا کلید گیت‌هابی ندارد (عامدانه: هیچ اعتبارنامه‌ای در آن نگه داشته نمی‌شود)
و روی پوش، گیت‌هاب چنین پاسخ می‌دهد:

```
fatal: could not read Username for 'https://github.com'
```

وضعیت ریپوی مقصد (`online-training-management-system`) اما مشکلی ندارد: **public
است و کامل خالی** — تازه ساخته شده و هیچ کامیتی ندارد. پس این پوش، پوشِ اول است و
هیچ تناقضی (non-fast-forward) پیش نمی‌آید.

برای همین دو راه دارید:

* **راه پیشنهادی:** از روی کامپیوتر خودتان پوش کنید — شما همان‌جا به‌عنوان صاحب
  ریپو لاگین هستید (Git Credential Manager یا VS Code / GitHub Desktop). چند دقیقه
  کار است و سند همین را توضیح می‌دهد.
* اگر می‌خواهید از همین workspace پوش انجام شود، باید یک توکن دسترسی (PAT) بدهید —
  که **در چت فرستادنش توصیه نمی‌شود**؛ توکن را بعداً باید باطل کنید.

---

## چرا پوشهٔ دانلودشده `.git` ندارد؟

فایل zip که دانلود می‌کنید از snapshot ساخته می‌شود و پوشهٔ `.git` عمداً داخل آن
نیست. یعنی فایل‌ها را دارید، ولی **تاریخچهٔ کامیت‌ها** را ندارید. برای همین
فایلی به نام `otms-git-backup.bundle` کنار پروژه گذاشته شده که **کل تاریخچه**
(۱۵ کامیت تا این لحظه) را دارد.

**تاریخچه دارد، پس چیزی گم نمی‌شود** — فقط باید اول از bundle بازگردانی شود.

---

## راه ۱ — اسکریپت آماده (ساده‌ترین)

در پوشهٔ پروژه:

```bat
tools\push-to-github.bat
```

اسکریپت خودش این‌ها را انجام می‌دهد:

1. اگر `.git` نبود، از `otms-git-backup.bundle` بازش می‌گرداند.
2. نشان می‌دهد چند کامیت دارد و آخرین کامیت چیست.
3. remote را ست می‌کند، `fetch` می‌زند و کامیت‌هایی که روی گیت‌هاب نیستند را
   نشان می‌دهد.
4. `git push` می‌زند.

> اگر ریپوی دیگری دارید (اسم عوض شده یا ریپوی جدید ساخته‌اید):
> ```bat
> tools\push-to-github.bat https://github.com/USER/REPO.git
> ```

## راه ۲ — دستی (۵ دستور)

اگر ترجیح می‌دهید خودتان دستورها را بزنید. در Command Prompt، داخل پوشهٔ پروژه
(همان‌جایی که `backend` و `otms_flutter` را می‌بینید):

```bat
:: ۱. اگر .git ندارید، تاریخچه را از بکاپ بازگردانید
git clone -b main otms-git-backup.bundle _restore
move /y _restore\.git .git
rmdir /s /q _restore

:: ۲. remote را وصل کنید (آدرس را با آدرس واقعی ریپوی خودتان عوض کنید)
git remote remove origin
git remote add origin https://github.com/seyedmohammadsinahosseini/online-training-management-system.git

:: ۳. ببینید چه چیزی پوش می‌شود
git fetch origin
git log --oneline origin/main..HEAD

:: ۴. پوش
git push -u origin HEAD:main
```

> **ریپوی خالی:** تا وقتی گیت‌هاب هیچ کامیتی نداشته باشد، `origin/main` وجود ندارد و
> دستور مقایسه در مرحلهٔ ۳ خطای `unknown revision` می‌دهد. این خطا طبیعی است — یعنی
> «همه‌چیز پوش می‌شود». مستقیم بروید سراغ مرحلهٔ ۴؛ پوش، کل تاریخچه را می‌برد.

خروجی مرحلهٔ ۳ **کامیت‌هایی را نشان می‌دهد که هنوز روی گیت‌هاب نیستند**. چون ریپوی
مقصد خالی است، انتظار داشته باشید **کل تاریخچه** را ببینید (۱۶ کامیت تا این لحظه).
اگر لیست خالی بود یعنی چیزی برای پوش نمانده (همه از قبل آنجاست) و اگر تعداد خیلی
کمتری دیدید یعنی `otms-git-backup.bundle` قدیمی دانلود شده — نسخهٔ تازهٔ workspace را
بردارید.

برای دیدن کل تاریخچهٔ لوکال (نه فقط پوش‌نشده‌ها):

```bat
git log --oneline
```

## احراز هویت موقع پوش

گیت‌هاب از سال ۲۰۲۱ **رمز حساب را قبول نمی‌کند**. اگر پوش از شما نام کاربری/رمز
خواست:

* **راحت‌ترین:** بگذارید Git Credential Manager خودش پنجرهٔ مرورگر را باز کند و
  لاگین کنید (روی ویندوز معمولاً همراه Git for Windows نصب است).
* **یا:** یک **Personal Access Token** بسازید —
  `github.com → Settings → Developer settings → Personal access tokens` — و موقع
  پرسیدن رمز، **توکن** را به‌جای رمز بگذارید (نام کاربری، همان نام کاربری گیت‌هاب).
  برای پوش به ریپوی خودتان، دسترسی `repo` (یا برای ریپوی عمومی: `public_repo`) کافی است.

> اگر پیام `repository not found` گرفتید و مطمئنید ریپو وجود دارد، یعنی private است
> و لاگین نیستید — یا آدرس عوض شده. آدرس درست را به اسکریپت بدهید.

## بعد از پوش موفق

پوشهٔ پروژه از این به بعد یک **ریپوی واقعی git** است. یعنی بقیهٔ کارها عادی می‌شود:

```bat
git status
git add -A
git commit -m "..."
git push
```

و `otms-git-backup.bundle` دیگر لازم نیست (untracked است؛ می‌توانید پاکش کنید یا
جای دیگری نگه دارید). **آن را کامیت نکنید** — یک کپی از کل تاریخچه است و حجم
ریپو را بی‌دلیل بزرگ می‌کند.

## اگر پوش با پیام `workflow` رد شد

اگر توکن شما اسکوپ `workflow` نداشته باشد، گیت‌هاب هر پوشی که فایل
`.github/workflows/...` بسازد یا تغییر دهد را رد می‌کند:

```
! [remote rejected] main -> main (refusing to allow a Personal Access Token to
  create or update workflow `.github/workflows/ci.yml` without `workflow` scope)
```

دو راه:

1. **توکن با اسکوپ `workflow`** (روش اصلی): توکن را با تیک `workflow` بسازید
   (یا Regenerate کنید) و دوباره پوش بزنید — تاریخچه دست‌نخورده می‌ماند.
2. **بدون فایل CI**: فایل از تاریخچه بیرون گذاشته می‌شود (هش کامیت‌های بعد از
   آن عوض می‌شود)، فایل روی دیسک می‌ماند و در `.gitignore` ثبت می‌شود تا
   دوباره پوش نشود. این کاری است که در همین ریپو انجام شد.

> پوش **اتمی** است: تا وقتی رد شود، هیچ کامیتی روی گیت‌هاب نمی‌نشیند. پس حالت
> نیمه‌کاره وجود ندارد.

## عیب‌یابی

| مشکل | علت | راه‌حل |
|---|---|---|
| `could not read Username for 'https://github.com'` | احراز هویت نشده | با Credential Manager لاگین کنید یا PAT بدهید |
| `repository not found` | ریپو private/جابه‌جا شده، یا اشتباه تایپی در نام کاربری | آدرس درست را به اسکریپت بدهید و لاگین باشید |
| `failed to push some refs` / `non-fast-forward` | روی گیت‌هاب کامیتی هست که این پوشه ندارد | `git pull --rebase origin main` سپس دوباره پوش. **force نکنید** |
| `src refspec main does not match any` | روی برنچی غیر از `main` هستید | اسکریپت از `HEAD:main` استفاده می‌کند، پس این خطا نباید پیش بیاید |
| فایل `otms-git-backup.bundle` در `git status` دیده می‌شود | فایل کمکی است، نه بخشی از پروژه | کامیتش نکنید؛ بعد از پوش پاکش کنید |
| `unknown revision origin/main` در مرحلهٔ ۳ | ریپو خالی است، شاخه‌ای روی گیت‌هاب نیست | طبیعی است؛ مستقیم `git push -u origin HEAD:main` بزنید |
| لیست پوش‌نشده‌ها خیلی کوتاه‌تر از انتظار است | bundle قدیمی دانلود شده | bundle تازه را از workspace بردارید و دوباره اجرا کنید |
