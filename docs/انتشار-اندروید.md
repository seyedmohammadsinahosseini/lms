# ساخت و انتشار APK امضاشدهٔ Android

نسخهٔ release عمداً با debug key ساخته نمی‌شود. برای ساخت نهایی باید مالک پروژه
یک application ID یکتا و یک keystore دائمی انتخاب کند. اگر keystore گم شود،
به‌روزرسانی همان برنامه با همان هویت بسیار دشوار یا ناممکن می‌شود.

## ۱) انتخاب شناسه

نمونه:

```text
io.github.USERNAME.lms
```

فقط حروف کوچک/عدد/underscore در هر بخش و حداقل سه بخش استفاده کنید. بعد از
انتشار، این شناسه را تغییر ندهید.

## ۲) ساخت keystore (یک بار)

JDK 17 یا جدیدتر لازم است:

```bash
LMS_KEY_ALIAS=lms bash tools/create_android_keystore.sh "$HOME/lms-release.jks"
```

`keytool` رمزها و مشخصات certificate را می‌پرسد. فایل و رمزها را در password
manager و یک backup رمزنگاری‌شدهٔ جدا نگه دارید. فایل `.jks` و
`android/key.properties` را commit نکنید.

## ۳) ساخت محلی

```bash
export LMS_API_BASE=https://LOGIN.serv00.net/api/v1
export LMS_APPLICATION_ID=io.github.USERNAME.lms
export LMS_KEYSTORE="$HOME/lms-release.jks"
export LMS_KEY_ALIAS=lms
export LMS_STORE_PASSWORD='...'
export LMS_KEY_PASSWORD='...'
bash tools/build_signed_apk.sh
```

script ابتدا dependencies، analyze و test را اجرا می‌کند؛ سپس APK universal
release را می‌سازد و در `releases/` قرار می‌دهد:

```text
lms-VERSION-universal.apk
lms-VERSION-universal.apk.sha256
```

فایل موقت `android/key.properties` حتی هنگام خطا پاک می‌شود.

امضا را نیز بررسی کنید:

```bash
$ANDROID_HOME/build-tools/36.0.0/apksigner verify \
  --verbose --print-certs releases/*.apk
sha256sum -c releases/*.sha256
```

## ۴) ساخت امن در GitHub Actions

Workflow آماده: `.github/workflows/release-android.yml`.

در **Repository → Settings → Secrets and variables → Actions** این secretها را
ثبت کنید:

| Secret | مقدار |
|---|---|
| `LMS_KEYSTORE_BASE64` | base64 کامل keystore |
| `LMS_KEY_ALIAS` | alias انتخاب‌شده |
| `LMS_STORE_PASSWORD` | رمز keystore |
| `LMS_KEY_PASSWORD` | رمز key |
| `LMS_API_BASE` | URL تولیدی ending `/api/v1` (برای tag build) |
| `LMS_APPLICATION_ID` | شناسهٔ یکتا (برای tag build) |

ساخت base64:

```bash
base64 -w 0 "$HOME/lms-release.jks" > keystore.base64   # Linux
base64 < "$HOME/lms-release.jks" | tr -d '\n' > keystore.base64  # macOS
```

محتوای فایل متنی را در secret بگذارید و خود فایل را پاک کنید. برای آزمایش،
workflow را دستی اجرا و API/application ID را وارد کنید. برای release رسمی یک tag
امضاشده یا معمولی بسازید:

```bash
git tag v1.0.0
git push origin v1.0.0
```

workflow APK را build و signature را verify می‌کند، SHA-256 می‌سازد و در GitHub
Release همان tag قرار می‌دهد.

## ۵) انتشار رزومه‌ای

در صفحهٔ GitHub Release این موارد را واضح بنویسید:

- لینک Web demo
- حداقل Android پشتیبانی‌شده (SDK 26 / Android 8.0)
- نام و version
- SHA-256
- اینکه APK خارج از Play Store است و Android ممکن است اجازهٔ «Install unknown
  apps» بخواهد
- سیاست داده/حریم خصوصی دمو

Google Play برای انتشار عمومی account و فرایندهای بیرونی خودش را می‌خواهد و برای
هدف رزومه اجباری نیست.

## مواردی که باید روی گوشی واقعی کنترل شوند

- نصب و اجرای release، نه فقط debug
- login و بازیابی session پس از بستن برنامه
- profile/password
- upload و دانلود خصوصی
- countdown و auto-submit آزمون
- نسخه‌های تکلیف
- بازشدن Live برای Jitsi/JaaS
- portrait، landscape و گوشی کوچک

این repository مسیر ساخت را آماده می‌کند، اما خود keystore، secretهای حساب و
انتشار خارجی فقط باید توسط مالک پروژه انجام شود.
