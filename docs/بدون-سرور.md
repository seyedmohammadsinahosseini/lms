# اجرای پروژه بدون سرور و بدون هزینه

پرسش: «اپ روی موبایل اجرا شود و لازم نباشد برای سرور هزینه بدهم؛ بک‌اند هم
طوری عوض شود که حتی بدون خرید سرور، به‌صورت لوکال روی خود گوشی اجرا شود.»

**پاسخ کوتاه: بله ممکن است** — ولی نه با PHP و MySQL. دلیلش فنی است و راه‌حلش
هم مشخص:

> اندروید و iOS **PHP و MySQL را اجرا نمی‌کنند.** این دو برای سرور ساخته شده‌اند،
> نه برای موبایل. هر راهی که «همان PHP روی گوشی اجرا شود» وعده بدهد، در عمل یا
> شبیه‌سازی سنگین است یا کاربر باید ترمینال نصب کند. پس برای اینکه بک‌اند روی خود
> گوشی زندگی کند، باید **به زبان خود گوشی بازنویسی شود**.

---

## سه راه با هزینهٔ صفر

| | راه | چطور کار می‌کند | هزینه | اجرا روی گوشی؟ | محدودیت اصلی |
|---|---|---|---|---|---|
| **A** | **بک‌اند داخل خود اپ** (Dart + SQLite) | منطق بک‌اند به Dart ترجمه می‌شود و دیتابیس SQLite داخل اپ می‌نشیند | ۰ | ✅ کامل، آفلاین | داده روی **یک گوشی** می‌ماند |
| **B** | هاست رایگان PHP | همان بک‌اند فعلی روی سرویس‌های رایگان (InfinityFree و مانندش) | ۰ | ❌ (نیاز به اینترنت) | کیفیت پایین سرویس‌های رایگان، تبلیغ، گاهی بدون HTTPS |
| **C** | PHP در مرورگر با PHP-WASM | PHP به WebAssembly کامپایل می‌شود و داخل مرورگر گوشی اجرا می‌شود؛ فایل‌های استاتیک روی GitHub Pages | ۰ | ⚠️ فقط در مرورگر، نه اپ | آزمایشی و پرریسک؛ برای این حجم پروژه توصیه نمی‌شود |
| **D** | PHP روی گوشی با Termux | نصب Termux + php + mariadb روی گوشی | ۰ | ⚠️ فقط برای خودتان | ترمینال لازم است، اپ‌مانند نیست، روی گوشی معمولی دردسر |

**پیشنهاد من: راه A.** چون تنها راهی است که واقعاً «اپ روی گوشی، بدون هیچ سروری»
است — نه ترمینال، نه مرورگر، نه اینترنت، نه تبلیغ، نه هزینه. ایرادش هم صریح است:
داده روی همان یک گوشی می‌ماند (پایین‌تر توضیح داده‌ام).

---

## ⚠️ محدودیت اصلی راه A — چند گوشی؟

پروژه یک **سیستم آموزش آنلاین** است: استاد تکلیف می‌دهد، دانش‌آموز تحویل می‌دهد.
اگر این دو نفر **دو گوشی جدا** دارند که باید دادهٔ مشترک ببینند، هیچ راه گوشی-محلی
کار نمی‌کند — چون دو گوشی بدون یک نقطهٔ مشترک نمی‌توانند داده را ببینند.

| حالت استفاده | راه درست |
|---|---|
| همه‌چیز روی **یک گوشی** (دمو، دفاع پروژه، استفادهٔ شخصی، حالت آفلاین) | ✅ راه A |
| استاد و دانش‌آموز روی **گوشی‌های جدا** | ❌ راه A کافی نیست → راه B (هاست رایگان) یا سرور |
| می‌خواهید هر دو را داشته باشید | ✅ راه A + کلید، یعنی کد طوری نوشته شود که با یک تنظیم به سرور وصل شود |

هر سه حالت با **یک معماری** پوشش داده می‌شوند (پایین‌تر: «حالت دوگانه»),
پس این تصمیم مسیر کد را نمی‌بندد.

## طراحی راه A

### نقطهٔ تعویض، فقط یک فایل است

خبر خوب: کل اپ (۹۳۵۳ خط Dart، ۳۸ فایل) **فقط از یک فایل** با بک‌اند حرف می‌زند:

```
lib/services/api_client.dart   ← ۴۷ متد (login, classes, submitAttempt, ...)
```

یعنی به‌جای دست‌زدن به ۳۸ فایل UI، فقط لایهٔ زیرین عوض می‌شود:

```
            ┌─────────────── UI اپ (۳۸ فایل) ───────────────┐
            │   بدون هیچ تغییری — همین‌که هست                  │
            └────────────────────┬───────────────────────────┘
                                 │  ۴۷ متد با همان امضاها
                    ┌────────────▼────────────┐
                    │  OmsApi  (interface)    │  ← لایهٔ جدید و نازک
                    └───────┬─────────┬───────┘
                            │         │
             ┌──────────────▼──┐   ┌──▼───────────────────┐
             │  LocalApi       │   │  HttpApi             │
             │  (Dart + SQLite)│   │  (همان بک‌اند PHP)   │
             │  پیش‌فرض جدید    │   │  برای حالت چندکاربره │
             └─────────────────┘   └──────────────────────┘
```

* `LocalApi` → داده در SQLite روی گوشی. بدون شبکه، بدون سرور.
* `HttpApi` → همان کد فعلی (`api_client.dart` عملاً همین است).
* انتخاب با یک تنظیم: `--dart-define=OTMS_API_BASE=...` یا یک گزینه در تنظیمات اپ.

### دیتابیس: همان ۱۷ جدول، در SQLite

`schema.sql` تقریباً بدون تغییر به SQLite منتقل می‌شود. تفاوت‌ها:

| MySQL | SQLite |
|---|---|
| `INT AUTO_INCREMENT` | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` | همان می‌ماند |
| `ENUM('a','b')` | `TEXT` + `CHECK (col IN ('a','b'))` |
| `DATE_ADD(NOW(), INTERVAL 30 DAY)` | `datetime('now','+30 days')` |
| `utf8mb4` | نیازی نیست (SQLite خودش UTF-8 است) |

جدول‌ها: `users, sessions, login_attempts, teacher_codes, classes, enrollments,
lessons, contents, assessments, questions, options, attempts, answers, homework,
submissions, qa_threads, qa_replies` — همه می‌مانند.

### احراز هویت

همان email/رمز. هش رمز با **PBKDF2-SHA256** (پکیج `crypto` + `pointycastle`)،
شبیه `password_hash` در PHP. نشست‌ها ساده می‌شوند: کاربر وارد‌شده در
`shared_preferences` ذخیره می‌شود، انقضا هم می‌ماند.

### فایل‌ها (محتوا و تکالیف)

الان فایل روی سرور در `backend/uploads/` می‌رود و با URL خوانده می‌شود
(`contents.file_path`, `submissions.file_path`). در حالت لوکال:

* آپلود → کپی در پوشهٔ اپ (`getApplicationDocumentsDirectory()/uploads/`)
* نمایش → مستقیم از فایل خوانده می‌شود (نه HTTP)
* دانلود/باز کردن → `url_launcher` روی `file://` (پکیج `open_filex` جایگزین مناسب)

یعنی سیستم آپلود امنیتی سرور (allowlist، محدودیت حجم) حذف نمی‌شود، بلکه به تابع
اعتبارسنجی Dart تبدیل می‌شود.

### دادهٔ نمونه

همان `tools/demo_seed.sql` (۵ کلاس، ۷ دانش‌آموز، آزمون‌ها، تکالیف، Q&A) به SQLite
منتقل می‌شود و **بار اول اجرای اپ** خودکار seed می‌شود. یعنی اپ نصب می‌شود و
بی‌درنگ پر از داده است — بدون هیچ دستور دستی.

### پشتیبان‌گیری — مهم است

وقتی داده فقط روی یک گوشی است، پاک‌کردن اپ = از دست رفتن همه‌چیز. پس:

* دکمهٔ **خروجی گرفتن** (فایل `.db` یا `.json` در پوشهٔ Downloads/اشتراک‌گذاری)
* دکمهٔ **بازیابی** از همان فایل
* (اختیاری) زمان‌بندی خودکار

## نقشهٔ مهاجرت: ۳۹ اندپوینت → ۸ ماژول Dart

اندپوینت‌ها ریز و تکراری‌اند؛ در Dart به ماژول‌های منطقی جمع می‌شوند:

| ماژول Dart | اندپوینت‌های PHP | کار |
|---|---|---|
| `auth.dart` | `login, register, logout, me` | ورود/ثبت‌نام/نشست |
| `codes.dart` | `code_get, code_lookup, code_regenerate` | کد استاد |
| `classes.dart` | `classes_list, class_create, class_delete, enroll, class_students` | کلاس‌ها |
| `lessons.dart` | `lessons_list, lesson_create, lesson_delete, contents_list, content_create, content_delete` | درس‌ها و محتوا |
| `assessments.dart` | `assessments_list, assessment_create, assessment_delete, assessment_get, question_add, question_delete` | آزمون و سؤال |
| `attempts.dart` | `attempt_submit, attempts_list, attempt_get, essay_grade` | پاسخ و نمره‌دهی |
| `homework.dart` | `homework_list, homework_create, homework_delete, submission_submit, submissions_list, submission_grade, submission_delete` | تکالیف |
| `qa.dart` | `qa_list, qa_create, qa_thread, qa_reply` | پرسش و پاسخ |

جمع: ۱۴۸۹ خط PHP → حدود **۱۲۰۰ تا ۱۸۰۰ خط Dart**، به‌علاوهٔ لایهٔ SQLite
(جست‌وجو/درج/به‌روزرسانی) و تست‌ها.

## فازبندی پیشنهادی

| فاز | کار | نتیجهٔ قابل‌دیدن | تخمین |
|---|---|---|---|
| ۰ | تصمیم‌های شما (جدول سؤال‌های پایین) | مسیر قطعی | — |
| ۱ | `OmsApi` interface + انتقال `api_client.dart` به `HttpApi` | اپ هنوز با PHP کار می‌کند، تست‌ها سبز | کوچک |
| ۲ | دیتابیس SQLite + مهاجرت schema + seed | تست دیتابیس، بدون UI | متوسط |
| ۳ | `LocalApi`: auth + classes + lessons | ورود و کلاس‌ها آفلاین روی گوشی | بزرگ |
| ۴ | `LocalApi`: assessments + attempts + نمره‌دهی | آزمون و نمره آفلاین | بزرگ |
| ۵ | `LocalApi`: homework + submissions + فایل‌ها + Q&A | تکالیف و آپلود روی گوشی | بزرگ |
| ۶ | کلید انتخاب حالت + پشتیبان‌گیری/بازیابی | هم لوکال، هم سروری | متوسط |
| ۷ | تست روی گوشی واقعی (APK) | اپ نهایی بدون سرور | متوسط |

هر فاز کامیت جدا دارد و در پایان هر فاز analyzer صفر و تست‌ها سبز می‌مانند.
فاز ۳ به بعد نیاز به نصب دوبارهٔ Flutter/SDK در محیط کاری دارد (بین جلسه‌ها پاک
می‌شود) — که مشکلی نیست، خودکار نصب می‌شود.

## و اگر بعداً سرور خواستید؟

راه A مسیر را نمی‌بندد. چون همه‌چیز پشت یک interface است، «سروری شدن» می‌شود
یک تنظیم:

```
LocalApi  ← پیش‌فرض (آفلاین، روی گوشی)
HttpApi   ← با دادن OTMS_API_BASE به هر سروری وصل می‌شود
```

و سرور می‌تواند یکی از این‌ها باشد:

* **هاست رایگان PHP** (بک‌اند فعلی دست‌نخورده بماند) — برای چند گوشی، با اینترنت
* یک VPS ارزان یا هر سرور دیگری، همان بک‌اند PHP
* یا بی‌سرور: همان SQLite + یک سرویس sync (کار بیشتری دارد، فعلاً لازم نیست)

یعنی **PHP را حذف نمی‌کنیم؛ فقط از مسیر بحرانی خارج می‌شود.**

## چه چیزی به همین سادگی «رایگان» نیست (صادقانه)

* **آفلاین روی یک گوشی ≠ چند کاربر واقعی.** اگر معلم و شاگرد روی گوشی‌های جدا
  باشند، بدون یک نقطهٔ مشترک (سرور/هاست) داده به هم نمی‌رسد.
* **راه A بازنویسی واقعی است** (حدود ۱۲۰۰–۱۸۰۰ خط Dart + تست). راه سریع‌تر برای
  «فقط نشان دادن پروژه» همان پیش‌نمایش وب است که داریم.
* **اپ‌استورها** اگر روزی بخواهید منتشر کنید: حساب گوگل‌پلی یک‌بار هزینهٔ ۲۵ دلاری
  دارد (برای تست شخصی با APK لازم نیست).
* راه C (PHP-WASM) روی کاغذ جذاب است ولی برای پروژه‌ای با ۳۹ اندپوینت و آپلود فایل،
  در عمل شکننده است — به‌عنوان راه اصلی پیشنهاد نمی‌شود.
