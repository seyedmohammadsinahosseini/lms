# اجرا روی گوشی واقعی از Android Studio

راهنمای قدم‌به‌قدم برای ویندوز. گوشی با کابل USB وصل است و می‌توانید کنترلش کنید،
پس فقط چند تنظیم مانده.

**اصل ماجرا:** اپ برای کار کردن به بک‌اند PHP نیاز دارد. روی **شبیه‌ساز** آدرس
`10.0.2.2` یعنی «کامپیوتر خودت»، ولی روی **گوشی واقعی** این آدرس معنی ندارد.
پس باید به اپ بگویید بک‌اند کجاست — این کار با `--dart-define` انجام می‌شود.

---

## ۱. پیش‌نیاز روی گوشی (یک بار برای همیشه)

1. **Developer options** را روشن کنید:
   `Settings → About phone → Build number` را **۷ بار** بزنید.
2. `Settings → System → Developer options → USB debugging` را روشن کنید.
3. گوشی را با کابل **دیتا** (نه کابل فقط-شارژ) به کامپیوتر بزنید.
4. روی صفحهٔ گوشی پیام **«Allow USB debugging?»** می‌آید → **Allow** (و اگر
   «Always allow from this computer» دارد، تیک بزنید).

> اگر این پیام را ندیدید، کابل را عوض کنید یا حالت USB را روی
> `File Transfer (MTP)` بگذارید. کابل‌های ارزان فقط شارژ هستند و داده رد و بدل نمی‌کنند.

---

## ۲. آی‌پی کامپیوتر را پیدا کنید

Command Prompt را باز کنید و بزنید:

```bat
ipconfig
```

در بخش کارت **Wi-Fi** (یا Ethernet)، خط **IPv4 Address** را بردارید:

```
Wireless LAN adapter Wi-Fi:
   IPv4 Address. . . . . . . . . . . : 192.168.1.15      ← این را بردارید
```

از این به بعد در دستورها `192.168.1.15` را با همین عدد عوض کنید.

**شرط مهم:** گوشی و کامپیوتر باید به **یک شبکهٔ Wi-Fi** وصل باشند. اگر گوشی روی
دیتای موبایل باشد کار نمی‌کند. (اگر Wi-Fi مشترک ندارید، برو به بخش **راه جایگزین:
`adb reverse`** در پایین — با کابل کار می‌کند و به Wi-Fi و فایروال کاری ندارد.)

---

## ۳. اجازهٔ دسترسی به Apache در فایروال ویندوز

ویندوز معمولاً اولین بار که Apache بالا می‌آید سؤال می‌پرسد. اگر قبلاً **Cancel**
زده‌اید، الان گوشی نمی‌تواند به بک‌اند وصل شود.

**راه ساده:** XAMPP Control Panel → Apache → **Config** → `httpd.conf` را باز
نگه دارید… نه، راحت‌تر: Command Prompt را **Run as administrator** باز کنید و:

```bat
netsh advfirewall firewall add rule name="OTMS dev HTTP" dir=in action=allow protocol=TCP localport=80
```

برای حذف بعدی:

```bat
netsh advfirewall firewall delete rule name="OTMS dev HTTP"
```

> **تست قبل از هر چیز:** مرورگر **گوشی** را باز کنید و این آدرس را بزنید:
> ```
> http://192.168.1.15/OTMS1/backend/api/me.php
> ```
> اگر `{"error":"Not authenticated"}` دیدید، شبکه و فایروال و Apache همه درست
> کار می‌کنند و می‌توانید بروید قدم بعد. اگر نه، **تا این حل نشود** اپ هم وصل
> نمی‌شود — این تست مشکل شبکه را از مشکل اپ جدا می‌کند.

---

## ۴. پروژه را در Android Studio باز کنید

⚠️ **مهم‌ترین نکتهٔ این راهنما:** پوشهٔ **`otms_flutter`** را باز کنید، نه ریشهٔ
مخزن.

```
✅ درست:  C:\xampp\htdocs\OTMS1\otms_flutter      ← اینجا pubspec.yaml دارد
❌ غلط:   C:\xampp\htdocs\OTMS1                   ← Android Studio آن را Flutter نمی‌شناسد
```

`File → Open…` → پوشهٔ `otms_flutter` را انتخاب کنید.

اگر اشتباه باز کردید، نشانه‌اش این است: دکمهٔ ▶ Flutter نمی‌آید و پنل چپ فایل‌ها را
مثل یک پروژهٔ معمولی نشان می‌دهد. `File → Close Project` و درست باز کنید.

### صبر کنید Gradle آماده شود

پایین‌راست پنجرهٔ Android Studio یک نوار پیشرفت می‌آید (`Gradle sync`,
`Indexing…`, `Downloading…`). **اولین بار چند دقیقه طول می‌کشد** چون Gradle و
وابستگی‌های اندروید دانلود می‌شوند. تا تمام نشدنش Run نزنید.

اگر خواست SDK نصب کند (پیام `Android SDK is missing` یا `SDK not found`):

`Tools → SDK Manager` → تب **SDK Platforms** → جدیدترین نسخه (مثلاً Android 16 /
API 36) را تیک بزنید → تب **SDK Tools** → `Android SDK Build-Tools` و
`Android SDK Platform-Tools` را تیک بزنید → **Apply**.

اگر خطای **JDK** داد (`Gradle requires JDK 17`): `File → Settings → Build,
Execution, Deployment → Build Tools → Gradle → Gradle JDK` را روی
**jbr-21** یا **Embedded JDK** بگذارید و **Apply**.

---

## ۵. برنامهٔ اجرا (Run Configuration) بسازید

از منوی بالا: **Run → Edit Configurations…** → روی **`+`** (بالا-چپ) → **Flutter**.

این‌ها را پر کنید:

| فیلد | مقدار |
|---|---|
| **Name** | `OTMS (phone)` |
| **Dart entrypoint** | `lib\main.dart` (پیش‌فرض درست است) |
| **Additional run args** | `--dart-define=OTMS_API_BASE=http://192.168.1.15/OTMS1/backend` |

⚠️ `192.168.1.15` را با آی‌پی **خودتان** عوض کنید (قدم ۲).

**`Additional run args` تنها فیلد مهم است.** بدون آن، اپ روی گوشی به `localhost`
وصل می‌شود که روی گوشی یعنی خودِ گوشی — و همهٔ درخواست‌ها با پیام
«Could not reach the server at …» شکست می‌خورند.

→ **OK**

> **راحت‌تر:** در مخزن سه کانفیگ آماده هست
> (`otms_flutter\.idea\runConfigurations\`) — «phone over Wi-Fi»، «phone over USB
> (adb reverse)» و «Android emulator». اگر بعد از باز کردن پروژه آن‌ها را در لیست
> Run دیدید، فقط آی‌پی کانفیگ Wi-Fi را ویرایش کنید و دیگر نیازی به ساختن دستی
> نیست. اگر ندیدید (مثلاً Android Studio آن‌ها را import نکرد)، همان بالا را
> دستی بسازید — نتیجه یکی است.

## ۶. گوشی را انتخاب و Run کنید

1. در نوار بالای پنجره، کنار دکمهٔ ▶ یک **dropdown** هست (احتمالاً نوشته
   `<no device>` یا نام یک شبیه‌ساز). روی آن بزنید — باید نام گوشی‌تان را ببینید،
   مثلاً `SM-A155F` یا `Pixel 7`.
2. همان را انتخاب کنید (اگر شبیه‌ساز هم دارید، **گوشی واقعی** را انتخاب کنید، نه
   `sdk gphone`).
3. کانفیگ `OTMS (phone)` را انتخاب کنید و **▶ Run** را بزنید (یا `Shift+F10`).

اگر گوشی در لیست نبود:

```bat
adb devices
```

باید چنین چیزی بدهد:

```
List of devices attached
R5CTB0XXXXX    device      ← اگر unauthorized نوشت، پیام Allow را روی گوشی تأیید کنید
                            ← اگر لیست خالی بود، کابل/درایور را چک کنید
```

`adb` داخل `C:\Users\<شما>\AppData\Local\Android\Sdk\platform-tools\adb.exe` است.

## ۷. اولین اجرا چه انتظاری داشته باشیم

- **بار اول طول می‌کشد** (۱ تا ۵ دقیقه): Gradle بیلد می‌کند، اپ نصب می‌شود، باز می‌شود.
- روی گوشی اجازهٔ **«Install via USB»** یا «نصب از منابع ناشناس» خواسته شد؟ اجازه بدهید.
- اپ با label **OTMS** نصب می‌شود و صفحهٔ «Welcome back» می‌آید.
- ورود با `teacher@otms.test` / `password` یا `student@otms.test` / `password`.

### بعد از اجرا

| کار | میان‌بر |
|---|---|
| تغییر کد با نگه‌داشتن state | `Ctrl+S` (Hot Reload) |
| ری‌استارت کامل اپ بعد از تغییر state | `Shift+Ctrl+\` (Hot Restart) |
| دیدن لاگ‌ها و خطاها | تب **Run** / **Logcat** پایین |

تغییرات کد را با `Ctrl+S` ببینید — نیازی به بیلد و نصب مجدد نیست.

## راه جایگزین: `adb reverse` (بدون Wi-Fi، بدون فایروال)

اگر Wi-Fi مشترک ندارید، یا فایروال اجازه نمی‌دهد، یا گوشی روی دیتای موبایل است،
این روش را استفاده کنید. پورت کامپیوتر را از طریق **کابل USB** به گوشی می‌آورد:

```bat
adb reverse tcp:8080 tcp:80
```

یعنی: «هر درخواست به `localhost:8080` روی گوشی را بفرست به پورت ۸۰ کامپیوتر.»
حالا در Run Configuration مقدار `Additional run args` را بگذارید:

```
--dart-define=OTMS_API_BASE=http://localhost:8080/OTMS1/backend
```

و Run بزنید.

> نکته‌ها:
> * `adb reverse` بعد از **جدا کردن کابل** یا ری‌استارت `adb` پاک می‌شود → دوباره بزنید.
> * پورت ۸۰ روی خود گوشی را bind نکنید (`tcp:80 tcp:80`) — روی گوشی غیر-روت شده
>   اجازه نمی‌دهد. همان `tcp:8080 tcp:80` درست است.
> * این روش ترافیک را از USB می‌برد، پس **سریع‌تر و پایدارتر** از Wi-Fi هم هست.

## عیب‌یابی

| مشکل | علت | راه‌حل |
|---|---|---|
| اپ می‌گوید «Could not reach the server at http://10.0.2.2/...» | `--dart-define` را ندادید، پس اپ پیش‌فرض شبیه‌ساز را استفاده می‌کند | قدم ۵: `Additional run args` را اضافه کنید و **دوباره Run** کنید (Hot Reload کافی نیست) |
| «Could not reach the server at http://192.168.1.15/...» | شبکه/فایروال/Apache | تست مرورگر گوشی در قدم ۳ را انجام دهید |
| `adb devices` خالی است | کابل یا حالت USB | کابل دیتا، حالت `File Transfer`، پیام Allow را تأیید کنید |
| دستگاه `unauthorized` است | پیام روی گوشی تأیید نشده | قفل گوشی را باز کنید، پیام «Allow USB debugging» را بزنید. اگر نیامد: `adb kill-server` بعد `adb start-server` |
| دستگاه `offline` است | adb گیر کرده | `adb kill-server && adb start-server` یا کابل را در پورت USB دیگری بزنید |
| Run غیرفعال (خاکستری) است | پروژه درست باز نشده یا دستگاه انتخاب نشده | پوشهٔ `otms_flutter` را باز کنید + دستگاه را از dropdown انتخاب کنید |
| `Gradle sync failed: Could not find SDK` | SDK در Android Studio تنظیم نشده | `Tools → SDK Manager` نصب کنید، بعد `File → Invalidate Caches / Restart` |
| `Unsupported class file major version` یا خطای JDK | Gradle JDK اشتباه | `Settings → Build Tools → Gradle → Gradle JDK` = **jbr-21** |
| `Gradle daemon disappeared` یا OutOfMemory | `gradle.properties` سقف heap را ۸ گیگ گذاشته (پیش‌فرض قالب Flutter) و رم سیستم کم است | در `otms_flutter\android\gradle.properties` مقدار `org.gradle.jvmargs` را به `-Xmx2G -XX:MaxMetaspaceSize=512m` کم کنید |
| صفحهٔ سفید یا اپ فوراً بسته می‌شود | خطای Kotlin/Java در بیلد | تب **Run** یا **Logcat** را ببینید؛ خطای دقیق آنجاست |
| اپ نصب می‌شود ولی «App not installed» می‌دهد | نسخهٔ قبلی با امضای دیگری نصب است | اپ OTMS قبلی را از گوشی حذف کنید و دوباره Run |
| اولین بیلد خیلی طول می‌کشد | Gradle و وابستگی‌ها دانلود می‌شوند | طبیعی است. دفعات بعد سریع‌تر (بیلد اینکرمنتال) |
| صفحهٔ گوشی خاموش می‌شود / اتصال قطع می‌شود | Doze یا بهینه‌سازی باتری | `Developer options → Stay awake` را روشن کنید |

## تفاوت‌ها با نسخهٔ وب

| | پیش‌نمایش وب | گوشی |
|---|---|---|
| آدرس بک‌اند | همان ماشینی که Apache روی آن است (`localhost`) | آی‌پی لن کامپیوتر، یا `localhost:8080` با `adb reverse` |
| فایل‌ها | از Apache سرو می‌شوند | داخل APK بسته‌بندی می‌شوند |
| رفتار | پنجرهٔ مرورگر | تمام‌صفحه، طراحی موبایل |

پس اگر روی گوشی چیزی کار نکرد ولی در پیش‌نمایش وب درست بود، تفاوت تقریباً همیشه
**آدرس بک‌اند** است — همان `--dart-define`. اول همان را چک کنید.

`usesCleartextTraffic="true"` در manifest هست، پس HTTP ساده روی شبکهٔ محلی کار
می‌کند. برای انتشار عمومی باید بک‌اند HTTPS شود و این گزینه حذف شود (بخش
Security notes در README اصلی).

## اگر بعداً خواستید APK بسازید (نصب بدون کابل)

```bat
cd C:\xampp\htdocs\OTMS1\otms_flutter
flutter build apk --release --dart-define=OTMS_API_BASE=http://192.168.1.15/OTMS1/backend
```

خروجی: `build\app\outputs\flutter-apk\app-release.apk` — این فایل را روی گوشی
کپی و نصب کنید.

> دسترسی `INTERNET` در manifest اصلی اضافه شده است؛ بدون آن نسخهٔ **release** هیچ
> درخواست شبکه‌ای نمی‌توانست بفرستد (قالب پیش‌فرض Flutter این مجوز را فقط در
> manifest دیباگ می‌گذارد که برای hot reload لازم است).
