# استقرار رایگان OTMS روی HelioHost

هدف این راهنما یک لینک رزومهٔ HTTPS است که Flutter Web، PHP API و MariaDB را
روی یک دامنه اجرا کند و همان API برای APK Android نیز قابل استفاده باشد.

## چرا HelioHost و نه InfinityFree؟

InfinityFree Free برای ورودی‌های API و اپ موبایل چالش اجباری JavaScript/cookie
دارد، CORS خارجی را نمی‌پذیرد و PHP را به `htdocs` محدود می‌کند. این محدودیت‌ها
با Android-first بودن OTMS و storage خصوصی خارج از document root سازگار نیستند.

HelioHost Free (سرور Johnny) PHP 8، MariaDB، Plesk، FTP، SSL رایگان و ۱۰۰۰ MB
فضا می‌دهد. ثبت‌نام رایگان Johnny ظرفیت روزانه دارد و در ساعت 00:00 و 12:00 UTC
باز می‌شود. فعال‌شدن دامنه ممکن است تا دو ساعت طول بکشد.

## ۱) ساخت حساب رایگان

1. به `https://heliohost.org/signup/` بروید.
2. پلن/سرور **Johnny (Free)** را انتخاب کنید.
3. اگر ظرفیت پر بود، ساعت 00:00 یا 12:00 UTC دوباره امتحان کنید.
4. یک subdomain مانند زیر انتخاب کنید:

```text
otmsdemo.helioho.st
```

5. پس از ثبت‌نام تا فعال‌شدن کامل Plesk و دامنه صبر کنید.

اطلاعات لازم برای ادامه:

- username حساب HelioHost
- نام server (معمولاً Johnny)
- دامنهٔ نهایی `*.helioho.st`

رمز حساب یا دیتابیس را در چت، issue یا commit قرار ندهید.

## ۲) ساخت MariaDB

در Plesk:

1. وارد **Databases** شوید.
2. **Add Database** را بزنید.
3. نامی مانند `otms` انتخاب کنید.
4. یک database user و رمز طولانی بسازید.
5. دسترسی remote را خاموش نگه دارید؛ PHP روی همان host به DB وصل می‌شود.
6. نام واقعی database و user را یادداشت کنید؛ Plesk معمولاً username حساب را
   به ابتدای آن‌ها اضافه می‌کند.

## ۳) ساخت بستهٔ مخصوص HelioHost

بعد از مشخص‌شدن دامنه، از ریشهٔ repository اجرا کنید:

```bash
OTMS_API_BASE=https://otmsdemo.helioho.st/api/v1 \
  bash tools/package_heliohost.sh
```

خروجی:

```text
deploy-heliohost/
├── httpdocs/       # Flutter Web و PHP API عمومی
├── config/         # env و کلیدهای خصوصی؛ خارج webroot
├── storage/        # فایل‌های خصوصی کاربران؛ خارج webroot
├── tools/          # ابزار CLI دعوت معلم
└── schema.sql
```

## ۴) آپلود بدون SSH

حساب shared رایگان HelioHost دسترسی SSH ندارد؛ از یکی از این‌ها استفاده کنید:

- Plesk File Manager
- FTP/FTPS که Plesk نمایش می‌دهد
- Git integration خود Plesk برای فایل‌های عمومی

محتوای پوشه‌ها را به این مقصدها منتقل کنید:

```text
deploy-heliohost/httpdocs/*  -> /httpdocs/
deploy-heliohost/config/*    -> /config/
deploy-heliohost/storage/*   -> /storage/
deploy-heliohost/tools/*     -> /tools/
```

`config` و `storage` نباید داخل `httpdocs` قرار بگیرند.

## ۵) تنظیم env خصوصی

در Plesk File Manager:

1. `/config/otms.env.example` را به `/config/otms.env` تغییر نام دهید.
2. permission را تا جای ممکن محدود کنید.
3. `OTMS_APP_KEY` را با یک مقدار تصادفی ۶۴ کاراکتری جایگزین کنید. اگر روی سیستم
   خودتان OpenSSL دارید:

```bash
openssl rand -hex 32
```

نمونهٔ تنظیم:

```dotenv
OTMS_APP_ENV=production
OTMS_APP_KEY=RANDOM_64_HEX_CHARACTERS
OTMS_DB_HOST=localhost
OTMS_DB_PORT=3306
OTMS_DB_NAME=نام-واقعی-دیتابیس-Plesk
OTMS_DB_USER=نام-واقعی-user-Plesk
OTMS_DB_PASS=رمز-واقعی-دیتابیس
OTMS_PUBLIC_BASE_URL=https://otmsdemo.helioho.st
OTMS_STORAGE_PATH=/home/PLESK-HOME/storage/uploads
OTMS_ALLOWED_ORIGINS=https://otmsdemo.helioho.st
OTMS_TRUST_PROXY=1
OTMS_DEMO_MODE=1
OTMS_ALLOW_TEACHER_REGISTRATION=0
OTMS_LIVE_PROVIDER=jaas
```

مسیر home دقیق را از File Manager بردارید. PHP در HelioHost می‌تواند فایل‌های
داخل home همان حساب را بخواند، ولی به home کاربران دیگر دسترسی ندارد.

## ۶) Import دیتابیس

1. در Plesk کنار database روی **phpMyAdmin** بزنید.
2. database خالی OTMS را انتخاب کنید.
3. تب **Import** را باز کنید.
4. فایل `deploy-heliohost/schema.sql` را Import کنید.
5. باید ۲۶ جدول ایجاد شود.

`tools/demo_seed.sql` را در سایت عمومی import نکنید. دکمهٔ Try demo دادهٔ مصنوعی
جدا و منقضی‌شونده می‌سازد.

## ۷) SSL و HTTPS

در Plesk:

1. **Websites & Domains → SSL/TLS Certificates** را باز کنید.
2. از **SSL It! / Let's Encrypt** گواهی رایگان بگیرید.
3. بعد از صدور موفق، redirect از HTTP به HTTPS را فعال کنید.

اگر صدور SSL خطا داد، موقتاً redirect اجباری HTTPS را خاموش کنید تا فایل اعتبارسنجی
Let's Encrypt روی HTTP قابل دسترسی باشد.

## ۸) کنترل نهایی

ابتدا health:

```text
https://otmsdemo.helioho.st/api/v1/health.php
```

سپس:

- [ ] صفحهٔ Web باز می‌شود.
- [ ] Try demo برای student و teacher کار می‌کند.
- [ ] ثبت‌نام و login/logout کار می‌کنند.
- [ ] teacher بدون invite در production ثبت‌نام نمی‌شود.
- [ ] ساخت کلاس، عضویت، آزمون، تکلیف و Q&A کار می‌کنند.
- [ ] آپلود در `/storage/uploads` است، نه `httpdocs`.
- [ ] signed download و authorization تست می‌شوند.
- [ ] درخواست API از Android debug روی همان HTTPS پاسخ می‌گیرد.
- [ ] origin ناشناس CORS مجاز نمی‌شود.

## ۹) Live و Android

برای Live تولیدی باید JaaS credentialها را در `/config/otms.env` و private key را
در `/config` قرار دهید. بدون JaaS، باقی برنامه کار می‌کند اما شروع Live تولیدی
خطای تنظیمات واضح می‌دهد.

پس از آنلاین‌شدن API، APK با همان URL ساخته می‌شود:

```text
https://otmsdemo.helioho.st/api/v1
```

مراحل signing در `docs/انتشار-اندروید.md` است.

## محدودیت‌های پلن رایگان

- حدود ۱۰۰۰ MB برای همهٔ فایل‌ها، دیتابیس، log، email و backup
- یک حساب رایگان به‌ازای هر شخص
- محدودیت CPU/RAM روزانه و امکان تعلیق در مصرف سنگین
- ثبت‌نام ظرفیت‌دار Johnny
- بدون SSH؛ مدیریت با Plesk/FTP

برای دمو رزومه مناسب است، اما برای دادهٔ واقعی حساس یا کاربران پرتعداد باید بعداً
به سرویس production ارتقا داده شود.
