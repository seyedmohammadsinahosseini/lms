# استقرار رایگان OTMS روی Serv00

هدف این راهنما ساخت یک لینک رزومهٔ HTTPS است که Flutter Web، PHP API و MySQL را
روی یک دامنه اجرا کند و همان API بدون چالش JavaScript برای APK Android نیز در
دسترس باشد.

## چرا Serv00؟

InfinityFree برای ورودی‌های API و اپ موبایل چالش اجباری JavaScript/cookie دارد،
CORS خارجی را نمی‌پذیرد و PHP را به `htdocs` محدود می‌کند. این محدودیت‌ها با
Android-first بودن OTMS و storage خصوصی خارج از document root سازگار نیستند.
ظرفیت رایگان HelioHost Johnny نیز ممکن است در یک روز پر باشد.

Serv00 رایگان، بدون تبلیغ و بدون کارت بانکی است و ۳ GB SSD، PHP 8.3، MySQL 8،
SSL رایگان، SFTP/SSH، backup روزانهٔ هفت‌روزه و subdomain رایگان
`LOGIN.serv00.net` ارائه می‌کند. حساب برای دموی رزومه مناسب است، اما SLA ندارد.

منابع رسمی:

- ثبت‌نام: `https://www.serv00.com/register-account/`
- امکانات: `https://www.serv00.com/`
- پنل: `https://docs.serv00.com/DevilWEB/`
- PHP/WWW: `https://docs.serv00.com/PHP/` و `https://docs.serv00.com/WWW/`
- MySQL: `https://docs.serv00.com/MySQL/`
- SSL: `https://docs.serv00.com/SSL/`

## ۱) ثبت درخواست حساب

1. به `https://www.serv00.com/register-account/` بروید.
2. اطلاعات واقعی، کشور و ایمیل در دسترس را وارد کنید.
3. یک login کوتاه و حرفه‌ای انتخاب کنید؛ دامنهٔ رایگان معمولاً از همان login
   ساخته می‌شود، مثلاً `otmsdemo.serv00.net`.
4. پاسخ سؤال ضدربات دربارهٔ نام سرویس میزبانی تجاری، طبق خود صفحه
   **hostUNO** است.
5. Terms را بپذیرید، reCAPTCHA را انجام دهید و فرم را ارسال کنید.
6. درخواست دستی بررسی می‌شود و طبق صفحهٔ ثبت‌نام ممکن است از چند ساعت تا ۷۲
   ساعت طول بکشد.

ایمیل فعال‌سازی معمولاً این موارد را می‌دهد:

- `Login`
- `Server` مانند `s12.serv00.com`
- آدرس پنل DevilWEB مانند `panel12.serv00.com`
- دامنهٔ رایگان مانند `LOGIN.serv00.net`
- رمز اولیه

برای ادامه فقط **Login، Server و Domain** لازم است. رمز حساب یا دیتابیس را در
چت، issue، commit یا screenshot عمومی قرار ندهید.

> طبق شرایط Serv00 اگر ۹۰ روز در DevilWEB یا SSH وارد نشوید، حساب ممکن است
> خودکار و بدون امکان بازیابی حذف شود. یک یادآور ماهانه برای login و backup
> تنظیم کنید.

## ۲) بررسی سایت PHP در DevilWEB

پس از فعال‌شدن حساب:

1. وارد DevilWEB شوید؛ شمارهٔ panel با شمارهٔ server یکسان است.
2. از **WWW websites** دامنهٔ `LOGIN.serv00.net` را باز کنید.
3. نوع سایت باید **PHP** باشد. اگر دامنه موجود نبود، آن را با نوع PHP اضافه کنید.
4. مسیر استاندارد سایت این است:

```text
/usr/home/LOGIN/domains/DOMAIN/public_html
```

5. گزینهٔ PoW را **Off** نگه دارید. فعال‌کردن browser challenge باعث می‌شود
   Android نتواند API را مستقیم صدا بزند.
6. Cache میزبان را هنگام استقرار اولیه Off نگه دارید و GZIP را می‌توانید روشن
   کنید.

## ۳) ساخت MySQL

در DevilWEB:

1. وارد **MySQL** شوید و **+ Add database** را بزنید.
2. یک نام مانند `otms` و یک user مجزا با رمز طولانی بسازید.
3. database، user و password واقعی نمایش‌داده‌شده را در password manager ذخیره
   کنید؛ نام‌ها ممکن است با login حساب prefix شوند.
4. host دیتابیس از شمارهٔ server ساخته می‌شود. برای نمونه:

```text
Server: s12.serv00.com
DB host: mysql12.serv00.com
```

5. remote database در پلن رایگان لازم نیست؛ PHP روی همان زیرساخت به
   `mysqlX.serv00.com` وصل می‌شود.

## ۴) ساخت بستهٔ مخصوص Serv00

پس از دریافت ایمیل فعال‌سازی، از ریشهٔ repository اجرا کنید:

```bash
export OTMS_SERV00_LOGIN=LOGIN
export OTMS_SERV00_SERVER=s12.serv00.com
export OTMS_SERV00_DOMAIN=LOGIN.serv00.net
export OTMS_API_BASE=https://LOGIN.serv00.net/api/v1
bash tools/package_serv00.sh
```

مقادیر نمونه را دقیقاً با اطلاعات ایمیل خود عوض کنید. خروجی:

```text
deploy-serv00/
├── public_html/    # Flutter Web و PHP API عمومی
├── config/         # env و کلیدهای خصوصی؛ خارج webroot
├── storage/        # upload، temp و log خصوصی؛ خارج webroot
├── tools/          # ابزار CLI دعوت معلم
├── .user.ini       # تنظیمات PHP همان دامنه
├── schema.sql
└── SERV00_DEPLOY.txt
```

اسکریپت عمداً فقط URL عمومی و اطلاعات غیرمحرمانهٔ حساب را می‌گیرد و هیچ رمز یا
secretی را در build قرار نمی‌دهد.

## ۵) آپلود امن با SFTP

Serv00 دسترسی SSH/SFTP دارد. در WinSCP، FileZilla یا Cyberduck:

```text
Protocol: SFTP
Host:     s12.serv00.com
Port:     22
Username: LOGIN
Password: رمز حساب خودتان
```

محتویات داخل `deploy-serv00`، از جمله فایل مخفی `.user.ini`، را به این مسیر
منتقل کنید:

```text
/usr/home/LOGIN/domains/DOMAIN/
```

ساختار نهایی باید چنین باشد:

```text
/usr/home/LOGIN/domains/DOMAIN/
├── public_html/
├── config/
├── storage/
├── tools/
├── .user.ini
└── schema.sql
```

`config`، `storage`، `tools` و `schema.sql` نباید داخل `public_html` قرار بگیرند.

اگر از SSH استفاده می‌کنید، permissionها را محدود کنید:

```bash
chmod 700 /usr/home/LOGIN/domains/DOMAIN/config
chmod 700 /usr/home/LOGIN/domains/DOMAIN/storage
chmod 700 /usr/home/LOGIN/domains/DOMAIN/tools
chmod 600 /usr/home/LOGIN/domains/DOMAIN/config/otms.env
```

## ۶) تنظیم env خصوصی

1. `config/otms.env.example` را به `config/otms.env` تغییر نام دهید.
2. `OTMS_APP_KEY` را روی کامپیوتر خود بسازید:

```bash
openssl rand -hex 32
```

3. فایل را با مقادیر واقعی تکمیل کنید:

```dotenv
OTMS_APP_ENV=production
OTMS_APP_KEY=RANDOM_64_HEX_CHARACTERS
OTMS_DB_HOST=mysql12.serv00.com
OTMS_DB_PORT=3306
OTMS_DB_NAME=نام-واقعی-database
OTMS_DB_USER=نام-واقعی-user
OTMS_DB_PASS=رمز-واقعی-database
OTMS_PUBLIC_BASE_URL=https://LOGIN.serv00.net
OTMS_STORAGE_PATH=/usr/home/LOGIN/domains/LOGIN.serv00.net/storage/uploads
OTMS_ALLOWED_ORIGINS=https://LOGIN.serv00.net
OTMS_TRUST_PROXY=0
OTMS_DEMO_MODE=1
OTMS_ALLOW_TEACHER_REGISTRATION=0
OTMS_LIVE_PROVIDER=jaas
```

`package_serv00.sh` مقدار host، URL و مسیر storage را خودکار تنظیم می‌کند؛ فقط
placeholderهای database و secretها باقی می‌مانند.

در **WWW websites → Details**، گزینهٔ Open Basedir باید حداقل domain root و
`/tmp` را اجازه دهد:

```text
/usr/home/LOGIN/domains/DOMAIN:/tmp
```

## ۷) Import دیتابیس

### روش ساده با phpMyAdmin

1. `https://pma.serv00.com/` را باز کنید.
2. با user و password همان MySQL وارد شوید.
3. database خالی OTMS را انتخاب کنید.
4. تب **Import** را باز کنید و `deploy-serv00/schema.sql` را وارد کنید.
5. باید ۲۶ جدول ایجاد شود.

### روش SSH

فایل package را قبلاً روی server گذاشته‌اید، پس می‌توانید اجرا کنید:

```bash
mysql --host mysql12.serv00.com --user DATABASE_USER -p \
  DATABASE_NAME < /usr/home/LOGIN/domains/DOMAIN/schema.sql
```

رمز بعد از اجرای دستور پرسیده می‌شود؛ آن را داخل command یا history ننویسید.

`tools/demo_seed.sql` را در سایت عمومی import نکنید. دکمهٔ Try demo دادهٔ مصنوعی
جدا و منقضی‌شونده می‌سازد.

## ۸) SSL و HTTPS

در DevilWEB:

1. وارد **SSL → WWW websites** شوید.
2. کنار IP سایت **Manage → + Add certificate** را بزنید.
3. **Generate Let's Encrypt certificate** را انتخاب کنید.
4. پس از صدور موفق، در **WWW websites → Details** گزینهٔ **Force SSL** را روشن
   کنید.

برای subdomain پیش‌فرض Serv00 معمولاً DNS از قبل درست است. اگر دامنهٔ شخصی
اضافه شود، A record باید پیش از صدور گواهی به Web IP حساب اشاره کند.

## ۹) کنترل نهایی

ابتدا health را باز کنید:

```text
https://LOGIN.serv00.net/api/v1/health.php
```

سپس این موارد را بررسی کنید:

- [ ] health با HTTP 200 پاسخ می‌دهد و secret نشان نمی‌دهد.
- [ ] صفحهٔ Flutter Web باز می‌شود و refresh route به 404 نمی‌رود.
- [ ] Try demo برای student و teacher کار می‌کند.
- [ ] ثبت‌نام و login/logout کار می‌کنند.
- [ ] teacher بدون invite در production ثبت‌نام نمی‌شود.
- [ ] ساخت کلاس، عضویت، آزمون، تکلیف و Q&A کار می‌کنند.
- [ ] فایل‌ها در `storage/uploads` هستند، نه `public_html`.
- [ ] signed download و authorization تست می‌شوند.
- [ ] درخواست API از Android debug روی همان HTTPS پاسخ JSON می‌گیرد.
- [ ] origin ناشناس CORS مجاز نمی‌شود.
- [ ] PoW یا challenge مرورگری Serv00 فعال نیست.

## ۱۰) Live و APK

برای Live تولیدی باید JaaS credentialها را در `config/otms.env` و private key را
در `config` قرار دهید. بدون JaaS، باقی برنامه کار می‌کند اما شروع Live تولیدی
خطای تنظیمات واضح می‌دهد.

APK باید با همین API ساخته شود:

```text
https://LOGIN.serv00.net/api/v1
```

مراحل signing در `docs/انتشار-اندروید.md` است.

## محدودیت‌ها و نگهداری

- ۳ GB فضا و ۵۱۲ MB RAM؛ مناسب دمو، نه کاربران پرتعداد
- بدون SLA و با حق مسدود یا حذف حساب در صورت تخلف یا مصرف غیرعادی
- بررسی دستی درخواست حساب، معمولاً چند ساعت تا ۷۲ ساعت
- حذف خودکار حساب بعد از ۹۰ روز بدون login به DevilWEB یا SSH
- backup روزانهٔ هفت‌روزه، ولی داشتن backup مستقل همچنان مسئولیت مالک است
- remote MySQL در پلن رایگان در دسترس نیست و برای OTMS لازم هم نیست

حداقل ماهی یک بار وارد پنل شوید و backup دیتابیس و فایل‌های خصوصی را خارج از
حساب نگه دارید. برای دادهٔ واقعی حساس یا استفادهٔ عمومی گسترده، بعداً به میزبان
پولی دارای SLA مهاجرت کنید.
