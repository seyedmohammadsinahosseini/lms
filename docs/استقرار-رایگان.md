# استقرار رایگان دمو روی Alwaysdata

هدف این راهنما یک لینک رزومهٔ HTTPS شامل Flutter Web، PHP و MariaDB است. GitHub
Pages به‌تنهایی مناسب نیست چون PHP اجرا نمی‌کند.

> پلن Free برای دمو و استفادهٔ غیرانتفاعی با منابع محدود است. قوانین و سهمیهٔ
> جاری Alwaysdata را هنگام ثبت‌نام دوباره بخوانید.

## چیزی که لازم دارید

- حساب Alwaysdata و نام account آن، مثلاً `myname`
- Flutter روی سیستم خودتان، یا artifact ساخته‌شده در GitHub Actions
- برنامهٔ SFTP مثل WinSCP/FileZilla یا دستور `scp`
- حدود ۳۰ دقیقه زمان

## ۱) حساب، دیتابیس و سایت

1. در Alwaysdata حساب Free بسازید.
2. در بخش **Databases → MariaDB** یک database و یک user جدا بسازید و رمز طولانی
   ذخیره کنید. نام‌ها معمولاً پیشوند account دارند.
3. در بخش **Web → Sites** یک سایت PHP بسازید.
4. آدرس رایگان مانند `https://ACCOUNT.alwaysdata.net` را انتخاب کنید.
5. فعلاً document root را یادداشت کنید؛ بعداً آن را روی پوشهٔ `www` بستهٔ ما
   می‌گذاریم.

رمز دیتابیس، کلید برنامه یا کلید Android را داخل Git/GitHub commit نکنید.

## ۲) ساخت بسته روی کامپیوتر

از ریشهٔ پروژه:

```bash
export OTMS_API_BASE=https://ACCOUNT.alwaysdata.net/api/v1
bash tools/package_deployment.sh
```

در ویندوز PowerShell (با Git Bash برای اجرای script):

```powershell
$env:OTMS_API_BASE='https://ACCOUNT.alwaysdata.net/api/v1'
bash tools/package_deployment.sh
```

خروجی `deploy-package` است:

```text
deploy-package/
  www/       ← document root و فایل‌های Web/API
  config/    ← تنظیمات خصوصی؛ بیرون document root
  storage/   ← فایل‌های خصوصی؛ بیرون document root
  schema.sql
```

اگر build release روی سیستم کم‌حافظه متوقف شد، repository را به GitHub push
کنید و artifact job `Flutter analysis, tests and builds` را دانلود کنید؛ یا build
را روی سیستم قوی‌تری انجام دهید. قبل از انتشار باید CI سبز باشد.

## ۳) آپلود

با SFTP/SSH فایل‌ها را زیر یک پوشهٔ اختصاصی در home حساب کپی کنید، مثلاً:

```text
/home/ACCOUNT/otms/www
/home/ACCOUNT/otms/config
/home/ACCOUNT/otms/storage
/home/ACCOUNT/otms/schema.sql
```

نمونهٔ خط فرمان (نام host را از پنل Alwaysdata بردارید):

```bash
ssh ACCOUNT@ssh-ACCOUNT.alwaysdata.net 'mkdir -p /home/ACCOUNT/otms'
scp -r deploy-package/. ACCOUNT@ssh-ACCOUNT.alwaysdata.net:/home/ACCOUNT/otms/
```

اگر نام SSH ارائه‌شده در پنل متفاوت بود، دقیقاً همان را استفاده کنید.

## ۴) تنظیم secretها

روی سرور:

```bash
cd /home/ACCOUNT/otms
mv config/otms.env.example config/otms.env
openssl rand -hex 32
chmod 700 config storage storage/uploads
chmod 600 config/otms.env
```

خروجی `openssl` را به‌عنوان `OTMS_APP_KEY` بگذارید. فایل
`config/otms.env` را با مقادیر واقعی ویرایش کنید:

```dotenv
OTMS_APP_ENV=production
OTMS_APP_KEY=خروجی-۶۴-کاراکتری-openssl
OTMS_DB_HOST=mysql-ACCOUNT.alwaysdata.net
OTMS_DB_PORT=3306
OTMS_DB_NAME=نام-واقعی-دیتابیس
OTMS_DB_USER=نام-واقعی-user
OTMS_DB_PASS=رمز-واقعی
OTMS_PUBLIC_BASE_URL=https://ACCOUNT.alwaysdata.net
OTMS_STORAGE_PATH=/home/ACCOUNT/otms/storage/uploads
OTMS_ALLOWED_ORIGINS=https://ACCOUNT.alwaysdata.net
OTMS_TRUST_PROXY=1
OTMS_DEMO_MODE=1
OTMS_ALLOW_TEACHER_REGISTRATION=0
OTMS_LIVE_PROVIDER=jaas
OTMS_JAAS_APP_ID=
OTMS_JAAS_KEY_ID=
OTMS_JAAS_PRIVATE_KEY_FILE=/home/ACCOUNT/otms/config/jaas-private-key.pem
```

برای شروع می‌توانید Live را بدون credential رها کنید؛ همهٔ قابلیت‌های دیگر کار
می‌کنند و Live خطای تنظیمات واضح نشان می‌دهد. `meet.jit.si` در production عمداً
قبول نمی‌شود. برای Live تولیدی، حساب JaaS و سه مقدار مربوطه را اضافه کنید.

## ۵) Import دیتابیس

دستور دقیق host/user/database را از پنل کپی کنید:

```bash
mariadb -h mysql-ACCOUNT.alwaysdata.net \
  -u DATABASE_USER -p DATABASE_NAME < /home/ACCOUNT/otms/schema.sql
```

رمز را در خود command ننویسید؛ بعد از `-p` وارد کنید. `tools/demo_seed.sql` را
روی سایت عمومی import نکنید.

## ۶) تنظیم document root و HTTPS

در پنل Sites:

1. document root را `/home/ACCOUNT/otms/www` بگذارید.
2. نسخهٔ PHP پشتیبانی‌شدهٔ 8.2 یا جدیدتر را انتخاب کنید.
3. HTTPS/Let's Encrypt و **Redirect HTTP to HTTPS** را روشن کنید.
4. اگر پنل اجازه می‌دهد، directory listing را خاموش نگه دارید (فایل `.htaccess`
   بسته هم آن را خاموش می‌کند).

چند دقیقه صبر کنید و سپس:

```text
https://ACCOUNT.alwaysdata.net/api/v1/health.php
```

باید JSON سالم نشان دهد. سپس صفحهٔ اصلی را باز و **Try demo** را تست کنید.

## ۷) کنترل نهایی

- [ ] HTTP خودکار به HTTPS می‌رود.
- [ ] health پاسخ می‌دهد و secret/stack trace نمایش نمی‌دهد.
- [ ] Try demo برای teacher و student sandbox مستقل می‌سازد.
- [ ] ثبت‌نام student، ورود/خروج و ویرایش profile کار می‌کند.
- [ ] teacher بدون دعوت نمی‌تواند در production ثبت‌نام کند.
- [ ] فایل آپلودشده URL مستقیم storage ندارد.
- [ ] URL امضاشده بعد از تغییر امضا رد می‌شود.
- [ ] origin ناشناس header نوع `Access-Control-Allow-Origin` نمی‌گیرد.
- [ ] حجم دیسک/دیتابیس پلن Free را در پنل پایش می‌کنید.

sandboxهای منقضی‌شده هنگام ساخت demo جدید پاک می‌شوند.

## ساخت دعوت معلم

از SSH و با همان env:

```bash
cd /home/ACCOUNT/otms
OTMS_ENV_FILE=/home/ACCOUNT/otms/config/otms.env \
  php tools/create_teacher_invite.php 24
```

این script داخل بستهٔ deployment قرار دارد. کد فقط یک بار نمایش داده می‌شود و
در مثال بالا ۲۴ ساعت اعتبار دارد.

## به‌روزرسانی بعدی

1. backup دیتابیس و storage بگیرید.
2. build جدید را در پوشه‌ای جدا آپلود کنید.
3. اگر migration جدید وجود دارد ابتدا روی staging امتحان کنید.
4. document root را به نسخهٔ جدید تغییر دهید یا فایل‌ها را اتمیک جایگزین کنید.
5. health و checklist بالا را دوباره اجرا کنید.

`backend/migrations/2026-10-02_full_remediation.sql` فقط برای ارتقای دیتابیس legacy
است؛ روی دیتابیسی که با schema جدید ساخته‌اید اجرا نکنید.
