# پیش‌نمایش OTMS در مرورگر

این سند توضیح می‌دهد چطور نسخهٔ وب پروژه را بسازید و در مرورگر — روی کامپیوتر یا
گوشی — ببینید و تست کنید، بدون نیاز به شبیه‌ساز یا گوشی.

---

## چرا نسخهٔ وب؟

اپ اصلی برای گوشی نوشته شده، اما همان کد روی وب هم اجرا می‌شود. این برای کار روی
طراحی خیلی مفید است:

- همان ویجت‌ها، همان تم، همان فلوها — چیزی جداگانه‌ای برای وب نوشته نشده
- لازم نیست اندروید استودیو یا گوشی وصل باشد
- از گوشی خودتان هم می‌توانید بازش کنید (روی همان Wi-Fi)

> ⚠️ تفاوت‌ها: اندازهٔ صفحه بزرگ‌تر است (طراحی برای موبایل است، پس فضا خالی
> دیده می‌شود)، `file_picker` برای انتخاب فایل رفتار مرورگر دارد، و
> `url_launcher` یک تب جدید باز می‌کند.

---

## ساخت پیش‌نمایش (۳ دستور)

```bash
cd otms_flutter
flutter build web --debug

mkdir -p ../preview/OTMS1
cp -r build/web/. ../preview/
ln -s ../../backend ../preview/OTMS1/backend     # ویندوز: mklink /D

cd .. && php -S 0.0.0.0:8080 -t preview
```

بعد `http://localhost:8080` را باز کنید.

**چرا این ساختار؟** چون اپ و API روی **همان origin** قرار می‌گیرند، پس:

- هیچ تنظیم CORS لازم نیست
- هیچ `--dart-define=OTMS_API_BASE` لازم نیست — اپ به‌طور خودکار origin خودش را
  به‌عنوان آدرس API برمی‌دارد (جزئیات در `lib/core/config/env.dart`)
- همان آدرس از گوشی هم کار می‌کند: `http://<IP-کامپیوتر>:8080`

```
preview/
├── index.html, main.dart.js, canvaskit/ …   ← خروجی flutter build web
└── OTMS1/
    └── backend → ../my_flutter_app/backend  ← لینک به API واقعی
```

---

## دیدن از گوشی

۱. IP کامپیوتر را پیدا کنید (`ipconfig` روی ویندوز، `ip addr` روی لینوکس).
۲. سرور را روی `0.0.0.0` بالا بیاورید (دستور بالا همین کار را می‌کند).
۳. اگر ویندوز فایروال پرسید، اجازهٔ دسترسی روی شبکهٔ **Private** را بدهید.
۴. در مرورگر گوشی: `http://192.168.1.15:8080`

فایل `C:\xampp\htdocs\OTMS1\backend\config.php` باید به دیتابیس همان کامپیوتر وصل
باشد؛ با پیش‌فرض XAMPP نیازی به تغییر نیست.

## دادهٔ نمونه

برای اینکه صفحه‌ها خالی نباشند:

```bash
mysql -u root otms < tools/demo_seed.sql
```

چه چیزی اضافه می‌شود:

| مورد | تعداد | توضیح |
|---|---|---|
| کلاس | ۵ | ریاضی، فیزیک، شیمی، ادبیات انگلیسی، مبانی کامپیوتر — هر کدام با رنگ خودش |
| دانش‌آموز | ۷ | `student1@otms.test` تا `student6@otms.test` با رمز `password` |
| درس + محتوا | ۱۴ + ۱۹ | شامل یادداشت، جزوه و ویدیو (لینک یوتیوب) |
| آزمون + سؤال | ۶ + ۱۷ | چهار نوع سؤال: چندگزینه‌ای، درست/غلط، بله/خیر، جای خالی، تشریحی |
| تلاش آزمون | ۱۵ | نمره‌ها از خود پاسخ‌ها محاسبه می‌شوند، نه دستی |
| تکلیف + ارسال | ۸ + ۱۰ | بعضی تصحیح‌شده، بعضی در انتظار تصحیح |
| پرسش‌وپاسخ | ۵ + ۸ | شامل پاسخ‌های استاد |

حساب‌های ورود:

| ایمیل | رمز | نقش |
|---|---|---|
| `teacher@otms.test` | `password` | استاد |
| `student@otms.test` | `password` | دانش‌آموز |
| `student1@otms.test` … `student6@otms.test` | `password` | دانش‌آموز |

برای ریست کامل، فقط `backend/schema.sql` را دوباره import کنید.

## چه چیزهایی را تست کنید

این‌ها مسیرهایی هستند که خودم با مرورگر headless کلیک کردم و تأیید شدند:

**استاد**
- ورود → داشبورد → «Total Students» و «Active Classes» از API می‌آیند (۱۹ و ۵)
- «My Classes» → تب‌ها: Lessons / Assessments / Homework / Q&A / Students / Live
- تب Lessons: درس‌ها با تیتر درست خوانده می‌شوند
- ساخت آزمون: تیتر، مدت، و افزودن سؤال‌های چهار نوع

**دانش‌آموز**
- ورود → داشبورد → کلاس‌ها، تکالیف و آزمون‌های واقعی
- «My Classes» → یک کلاس → تب Assessments → دکمهٔ Start
- **انتخاب گزینه‌ها** (این مسیر بعد از مهاجرت `RadioGroup` بازنویسی شد)
- نوشتن پاسخ تشریحی و **Submit** → تلاش در دیتابیس ثبت می‌شود، سؤال چندگزینه‌ای
  خودکار نمره می‌گیرد و سؤال تشریحی «در انتظار تصحیح» می‌ماند

برای چک کردن نتیجهٔ Submit از دیتابیس:

```bash
mysql -u root otms -e "SELECT id, student_id, score, status FROM attempts ORDER BY id DESC LIMIT 3;"
```

## نکاتی که موقع کار با این پیش‌نمایش به آن‌ها خوردم

### ۱. انکودینگ متن در import دیتابیس
اگر `schema.sql` را با کلاینت mysql که charset پیش‌فرضش latin1 است import کنید،
متن نمونه خراب می‌شود — مثلاً «Chapter 1 â€" Fractions» به‌جای «Chapter 1 — Fractions».
این در فایل `schema.sql` و `tools/demo_seed.sql` با `SET NAMES utf8mb4;` حل شد.
اگر دیتابیس قدیمی دارید، دوباره import کنید.

### ۲. دو FloatingActionButton با tag یکسان
تب‌های کلاس (`TLessonsTab`، `TAssessmentsTab`، `THomeworkTab`) هر کدام
`Scaffold` با FAB خودشان دارند و `TabBarView` چند تب را همزمان زنده نگه می‌دارد.
نتیجه: خطای زمان اجرا در کنسول مرورگر —

```
There are multiple heroes that share the same tag within a subtree.
multiple heroes had the following tag: <default FloatingActionButton tag>
```

رفع شد با اختصاص `heroTag` یکتا به هر FAB.

### ۳. ذخیره‌سازی بلاک‌شده در مرورگر
`shared_preferences` روی وب اگر `localStorage` بلاک باشد (حالت ناشناس، iframe
سندباکس‌شده) استثنا می‌دهد. چون `AuthProvider.bootstrap()` قبل از نمایش هر چیزی
منتظر آن می‌ماند، اپ روی صفحهٔ لودینگ گیر می‌کرد. الان در این حالت نشست فقط در
حافظه نگه داشته می‌شود و اپ کار می‌کند.

## بیلد برای انتشار

`--debug` برای توسعه است (کامپایل سریع، فایل بزرگ). برای انتشار:

```bash
flutter build web --release
```

خروجی کوچک‌تر و سریع‌تر است ولی کامپایلش روی ماشین کم‌حافظه خیلی طول می‌کشد
(روی این سندباکس دو هسته‌ای و ۲ گیگ رم، بیلد release تمام نشد).
اگر روی سیستمی با رم کم گیر کردید، `--debug` را نگه دارید یا از
`flutter build web --release --no-tree-shake-icons` استفاده کنید.

| متن‌های عجیب مثل `â€"` | انکودینگ import | `schema.sql` را با `SET NAMES utf8mb4` که الان داخلش هست دوباره import کنید |
| تغییرات کد دیده نمی‌شود | سرویس‌ورکر کش کرده | `Ctrl+Shift+R` یا DevTools → Application → Unregister service worker |
