# پیش‌نمایش LMS در مرورگر

نسخهٔ وب همان backend واقعی را استفاده می‌کند و برای رزومه responsive است.
بهترین حالت، سرو Web و API از یک origin است؛ در توسعهٔ محلی CORS صریح نیز
پشتیبانی می‌شود.

## اجرای توسعه‌ای

API را از ریشهٔ پروژه اجرا کنید:

```bash
php -S 0.0.0.0:8080 -t backend
```

سپس:

```bash
cd lms_flutter
flutter run -d chrome --web-port=3000 \
  --dart-define=LMS_API_BASE=http://127.0.0.1:8080/api/v1 \
  --dart-define=LMS_APP_MODE=development
```

`http://127.0.0.1:3000` باید در `LMS_ALLOWED_ORIGINS` باشد. احراز هویت وب از
cookie نوع HttpOnly و CSRF استفاده می‌کند؛ token در localStorage نگهداری
نمی‌شود.

## دمو رزومه

برای نمایش عمومی، `LMS_APP_MODE=portfolio_demo` و `LMS_DEMO_MODE=1` سمت سرور
را فعال کنید. دکمهٔ **Try demo** برای هر بازدیدکننده دادهٔ synthetic جدا می‌سازد
که بعداً منقضی می‌شود. seed SQL را در دیتابیس عمومی import نکنید.

## build انتشار

```bash
cd lms_flutter
flutter build web --release --no-wasm-dry-run \
  --dart-define=LMS_API_BASE=https://LOGIN.serv00.net/api/v1 \
  --dart-define=LMS_APP_MODE=portfolio_demo
```

خروجی در `build/web` است. بازکردن مستقیم `index.html` با `file://` روش درستی
نیست؛ آن را با یک web server سرو کنید.

اسکریپت بسته‌بندی توصیه‌شده:

```bash
LMS_SERV00_LOGIN=LOGIN \
LMS_SERV00_SERVER=s12.serv00.com \
LMS_SERV00_DOMAIN=LOGIN.serv00.net \
LMS_API_BASE=https://LOGIN.serv00.net/api/v1 \
  bash tools/package_serv00.sh
```

جزئیات در `استقرار-رایگان.md` است.

## smoke test مرورگر

پس از build:

```bash
cd tools && npm ci && npx playwright install chromium && cd ..
python3 -m http.server 8080 --directory lms_flutter/build/web &
APP_URL=http://127.0.0.1:8080 node tools/web_smoke_test.js web-smoke.png
```

تست وقتی Flutter boot نشود، asset داخلی خطا بدهد، یا خطای JavaScript/console
رخ دهد fail می‌شود. همین مسیر در CI اجرا می‌شود.

## نکات

- GitHub Pages فقط فایل static اجرا می‌کند و PHP/MariaDB ندارد؛ به‌تنهایی برای
  این پروژه کافی نیست.
- اگر frontend و API روی دامنه‌های متفاوت‌اند، origin دقیق frontend را در CORS
  بگذارید و هر دو را با HTTPS سرو کنید.
- release Web در سیستم کم‌حافظه ممکن است هنگام `dart2js` متوقف شود؛ CI برای
  تأیید build نهایی در نظر گرفته شده است.
